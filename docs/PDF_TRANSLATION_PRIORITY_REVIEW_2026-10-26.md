# 번역 우선 적용·검토·원문 복원

## 사용자 재확인 후 수정: 실제 실행 서버와 적용 후 검토

사용자가 최근 생성한 27페이지 문서에서는 이전 서버 프로세스가 계속 실행되고 있었다. 실행 서버의 OpenAPI에 `restored_regions`가 없었고, 해당 실행 보고서에도 검증 버전이 없었다. 33개 미반영 기록 중 30개에 이전 사각형 겹침 차단 문구가 남아 있었다. 코드 수정만으로 실행 중인 Python 모듈과 기존 결과가 갱신되지는 않았다.

이전 후속 코드에도 빈 공간 재배치 후 충돌 검사를 통과하지 못하면 원문을 유지하는 경로가 남아 있었다. 이를 수정해 안전한 배치를 먼저 시도하고, 실패하면 **번역문 전체가 페이지 안에 표시되는 후보를 적용하고 겹침·영역 경계 위험을 검토 사유로 기록**한다. 문자열 누락·페이지 밖 잘림·소유하지 않은 원문 삭제·복잡한 이미지 배경 손상은 여전히 미반영 사유다. 검토 상태가 번역 적용 취소를 뜻하지 않는다. 검증 버전은 4로 올렸으며 구형 결과 화면에는 재생성이 필요하다고 표시한다.

같은 원문이 일반 텍스트와 OCR 기록으로 중복 인식된 경우에는 원문 유사도와 실제 위치, 또는 같은 표 칸의 번호 조각이라는 근거로 연결한다. 한 위치에 번역을 두 번 넣지 않으며, 대안 번역은 별도 기록으로 남긴다. 서로 다른 번역이면 문구 검토를 표시하고, 어느 기록에서 수동 적용·복원하더라도 같은 물리적 영역 전체에 적용한다. 원문의 문구·페이지 번호·파일명에 따른 예외는 사용하지 않는다.

표 안에서 원래 크기·굵기·색상이 같은 여러 줄은 같은 셀 안에서 한 크기로 재배치한 뒤 유사 셀의 크기 조정에 포함한다. 제목이나 서로 다른 서식을 가진 블록은 유지한다. 자동 번역에 원문 인식 실패 표시 `[OCR]`가 그대로 남은 경우는 레이아웃 충돌과 구분하여 미완성 교체문으로 표시한다. 사용자가 완성된 교체문을 입력하면 다시 적용할 수 있다.

PDF 서버를 기존 8011 포트에서 재시작하고 `/api/config`의 `render_version: 4`를 확인했다. 기존 번역문으로 새 실행을 생성하므로 번역 API를 다시 호출하지 않는다. 원본과 이전 실행은 보존한다. 회귀 테스트는 **Python 230개와 Node 2개 통과**했으며, 충돌 후 번역 적용·검토 표시·원문 복원, 중복 OCR 수동 적용/복원, 표 내 여러 줄 크기 통일을 포함한다.

실제 27페이지 문서의 새 실행은 `3225f779be4a4192bd5dfe7faa89c2bb`이다. 저장된 이전 실행의 번역 적용 808개/미반영 33개가 **적용 833개/미반영 8개**로 바뀌었다. 이전의 사각형 겹침 차단 30개 중 **29개가 적용**됐고 나머지 1개는 `[OCR]`가 남은 미완성 교체문이다. 중복 인식 14개는 대표 영역을 통해 한 번만 삽입하므로 위 수치는 물리적 문장 수가 아닌 영역 기록 수다. 적용된 영역 중 228개는 재배치·가독성·중복 번역 문구 등을 검토하도록 표시한다. 페이지 기하·구조 검사는 통과했고 허용 수정 범위 밖 변경 픽셀은 0이다. 2·6페이지의 실제 표와 도식은 Poppler로 렌더링해 확인했다. 배경 지우기 경계와 원문 인식/번역의 문구 품질까지 완벽하다는 뜻은 아니다.

남은 8개는 공간 부족 2개, 문자 출력 불일치 3개, `[OCR]`가 남은 교체문 2개, 복잡한 배경 1개다. 번역은 따로 보관한다. 이 결과는 최신 작업 기록에 저장했고 이전 실행은 그대로 열 수 있다.

최근에 다시 처리된 1번 과제 34페이지 문서도 실행 서버에서 갱신했다(`66127fac22344817bc26bdff5c8e912e`). 이전 적용 928개/미반영 60개에서 **적용 985개/미반영 2개**가 됐다. 이전 미반영 중 57개가 적용되고 1개는 번역 변경이 없는 기록으로 보존됐다. 적용 후 검토는 180개이며, 남은 2개는 작거나 흐린 이미지의 원문 인식 문제다. 페이지 기하·구조 검사 통과, 텍스트/유지 영역 검사 불일치 및 허용 수정 범위 밖 변경 픽셀은 0이다. 두 실제 문서와 별개로, 충돌이 실제로 남는 합성 사례에서도 번역문 전체가 삽입되고 `applied=true`, `review_required=true`가 함께 기록되며 원문 복원이 가능함을 회귀 테스트로 확인했다.

아래는 이 추가 수정 이전의 첫 후속 점검 기록이다.

2026-10-26 후속 점검. 기존 번역 API, 번역 캐시, 입력 PDF, 과거 실행 결과는 변경하지 않았다. 실제 저장 번역을 다시 조판해 비교했다. 이 기록은 같은 날짜의 첫 레이아웃 보존 점검 이후 변경사항이다.

## 확인한 원인

PDF 자체에는 Word처럼 표를 늘리고 다음 문단을 이동하는 자동 조판 규칙이 없다. 그러나 이번에 반복된 `배치 영역이 이웃 영역과 겹칩니다`는 PDF의 필연적 한계가 아니라, 여백까지 포함한 사각형 겹침을 실제 글자 충돌처럼 취급한 엔진의 판단이었다.

| 원인 | 실제 확인 | 개선 |
|---|---|---|
| 배치 사각형의 여백 겹침 | 원문 글자는 떨어져 있어도 사각형 면적이 0.5pt² 넘게 겹치면 중단 | 사각형 겹침은 진단에 기록. 실제 glyph·이미지 잉크·객체 경계로 검사 |
| 인접 행의 글꼴 경계 겹침 | ascender/descender 경계가 겹쳐 전체 블록 삭제가 위험 | 각 소유 글자의 배타적 내부에 작은 삭제 영역을 배치. 모든 이웃 원문 글자를 대조 |
| 스캔 배경 패치의 겹침 | 사각형 전체를 덮는 패치가 이웃의 원문을 다시 칠할 수 있음 | 삭제 마스크만 불투명하게 만들고 이웃 글자 부분은 투명하게 보호 |
| 구형 분석의 목록 기호 경고 | 34페이지 문서의 36개 영역에 확인된 목록 기호 경고가 남음 | 기존 `repair_symbols` 규칙을 저장 분석에도 적용. 미확인 사설 문자는 계속 보류 |
| 단위 문자 표시 실패 | 22페이지 문서의 7개 영역에서 ㎥·㎛·㎎가 NUL로 추출됨 | 모든 조판 경로의 출력 직전에 Unicode 호환 단위를 동등한 표시 문자로 변환. 원문·API 번역 문자열 유지 |
| 실제 공간 부족·인식 문제 | 작은 OCR 라벨, 체크 표시 분리 실패, 여러 칸을 묶은 과거 도식 분석 | 안전한 후보 공간과 줄바꿈을 재시도. 끝내 들어가지 않거나 소유 관계를 확인할 수 없으면 별도 미반영 진단 |

72dpi 원문 유지 검사에서는 반올림한 자르기 영역에 이웃 행 픽셀이 들어가는 오탐도 확인했다. 경계에서 변화가 발견되면 해당 부분을 288dpi로 다시 렌더링해 실제 영역 내부만 비교한다. 원문 내부를 실제로 변경한 테스트는 계속 실패한다. 글자 검증은 위치·크기·색·글꼴·스타일을 비교하되, 주변 문맥에 따라 추론되는 superscript 비트는 직접 서식으로 간주하지 않는다.

## 동작 변경

`placement_resolution.py`에 공통 처리를 모았다. 일반 조판과 기존 공간 회복이 실패하면, 실제 장애물 사이의 빈 직사각형 안에서 여백·행간·단어 줄바꿈을 조정한다. 각 후보는 임시 페이지에 실제 렌더링하여 문자 완전성, 경계, 충돌을 확인한 뒤 채택한다. 원본 위치를 지우는 범위와 번역을 배치하는 범위는 별도로 관리한다.

결과에는 `source_text`, `translated_text`, `applied`, `review_required`, `review_reasons`, `failure_category`를 기록한다. 기존 FIT/ADJUSTED/UNCHANGED/NEEDS_REVIEW 상태의 호환성은 유지한다. FIT/ADJUSTED이면서 `review_required=true`인 결과가 **번역 적용 후 검토 대상**이다. 단순한 사각형 겹침이 실제 충돌 없이 해소되면 그것만으로 검토 표시를 하지 않는다. 전체 블록 재배치, 큰 축소, 표의 크기 예외, 이미지 삭제 경계 조정에는 구체적인 검토 사유를 표시한다.

화면에서 **이 영역을 원문으로 복원**을 누르면 해당 페이지를 원본 PDF에서 다시 만들고 다른 영역의 번역을 적용한다. 추출한 원문을 대체 글꼴로 다시 쓰는 방식이 아니므로 원본 글자·이미지가 복원된다. 번역문은 삭제하지 않으며 **보관된 번역문 다시 적용**으로 다시 넣을 수 있다. 최신 실행 ID를 검사해 오래된 화면에서 다른 결과를 덮어쓰지 않는다. DOCX 수동 편집 이후에는 이 PDF 복원 경로를 차단한다.

표 글자 크기는 실제 검출된 표 안에서 원래 크기·굵기·글꼴 계열·색상이 비슷한 항목끼리 맞춘다. 일관성을 위한 일괄 축소는 원문 대비 15% 이내로 제한하고 사용자의 더 엄격한 최소 크기·축소 비율도 지킨다. 모든 셀을 가장 작은 셀의 크기로 낮추지 않으며, 제목·본문·특수 회전 항목은 구별한다. 한 셀 안에 여러 독립 서식 블록이 있는 경우는 기존 계층을 유지한다. 공통 크기로 안전하게 들어가지 않는 셀은 개별 크기를 사용하고 검토 대상으로 표시한다.

## 실제 문서 비교

아래 수정 전 수치는 **이번 후속 작업 직전 코드**로 같은 입력·레이아웃·번역 정책을 실행한 결과다. 2/4/34페이지는 첫 점검의 재실행 산출물을 사용했고, 22페이지는 이번 수정 전에 복사한 엔진으로 별도 재실행했다. 과거 업로드 시점의 보고서와 혼동하지 않는다.

| 문서 | 수정 전 번역 적용 / 미반영 | 수정 후 번역 적용 / 미반영 | 적용된 번역 중 검토 표시 |
|---|---:|---:|---:|
| 2페이지, 31영역 | 2 / 0 | 2 / 0 | 0 |
| 4페이지, 132영역 | 118 / 6 | 121 / 3 | 66 |
| 22페이지, 1,329영역 | 793 / 70 | 845 / 18 | 87 |
| 34페이지, 1,151영역 | 830 / 63 | 888 / 4 | 288 |

나머지 영역은 번역 변경이 없는 원문·기호 등이다. 검토 필요와 미반영은 다르며, 적용된 영역 중에도 줄바꿈·가독성·OCR 경계 검토가 남는다. 상세 목록은 `output/pdf/translation-priority/region-diagnostics.json`에 이전 사유, 새 결과, 원문·번역문, 보호 범위 보정과 표 크기 조정 정보를 함께 기록한다.

현재 실제 문서 네 종류 모두 페이지 기하·이미지·벡터·링크/주석 등 구조 검사 통과, 텍스트/유지 영역 검사 불일치 0건, 허용된 수정 범위 밖 변경 픽셀 0건이다. 이는 번역 의미나 모든 시각 품질의 완전한 보장을 뜻하지 않는다.

## 검증 및 사용

- PDF Lab 전체 **222개 통과**, Node 좌표 테스트 **2개 통과**, JavaScript 구문 검사와 `git diff --check` 통과.
- 기존 테스트 중 ‘사각형 겹침이면 반드시 원문 유지’ 기대치는 새 요구에 맞춰 변경했다. 대신 번역문 적용 여부, 이웃 원문 유지, 실제 glyph 충돌 없음, 검토 상태를 검사한다. 기존 글자 손상·누락 검사는 유지했다.
- 추가 회귀 사례: 원문 복원→번역 재적용→실행 이력 유지, 스캔 원문 픽셀 복원, 표 본문 크기 통일과 제목 유지, 분리 불가능한 겹친 원문 글자 보호, 단순 사각형 겹침의 오탐 방지, 투명 패치, 픽셀 경계 오탐과 실제 손상 구분, 알려진/모르는 목록 기호, 단위 문자와 간격 설정 조합.
- 브라우저에서 번역 적용 후 검토 표시, 원문 복원, 번역문 보관, 재적용을 실제 클릭해 확인했다. UI 검증에는 합성 문서만 사용했다.
- 합성 6종 18페이지와 실제 2/4/22/34페이지, 총 80페이지를 원본/출력 쌍으로 렌더링했다. 자동 검사는 모든 페이지, 육안 검토는 대표 표·스캔·본문·회전 사례와 상세 영역에 수행했다.
- 기존 번역 API를 새로 호출하지 않았으며 기존 backend/frontend 구현도 변경하지 않았다. 저장된 결과 PDF는 자동 변경되지 않으므로 서버에 새 코드를 반영한 뒤 **재생성**해야 새 처리가 적용된다.

```powershell
cd pdf-layout-lab
../backend/.venv/Scripts/python.exe -m pytest tests -q
node --test tests/test_geometry.cjs
../backend/.venv/Scripts/python.exe check_preservation.py ../output/pdf/translation-priority/synthetic
../backend/.venv/Scripts/python.exe check_preservation.py OUTPUT --saved-run RUN_DIRECTORY --source SOURCE_PDF
```

실제 문서의 새 PDF, 보고서, 페이지 비교 이미지는 `output/pdf/translation-priority/real-*/`에 있다. `summary.json.before`는 과거 저장 보고서이고, 이 표의 기준은 `region-diagnostics.json.before`다. 기존 업로드와 실행 폴더는 수정하지 않았다.

## 남은 한계

현재도 실제 글자를 안전하게 지울 수 없거나, 설정한 최소 크기에서 번역문을 모두 넣을 수 없는 경우에는 원문을 유지한다. 번역문은 별도로 보관되므로 영역을 수정하거나 더 짧은 번역을 입력하여 재적용할 수 있다. 22페이지의 남은 18개는 공간 부족 8개, 체크 표시/설명 분리 불확실 6개, 흐린 이미지 원문 4개다. 4페이지의 3개는 작은 OCR 라벨의 공간 부족이다. 34페이지의 4개는 경계/이웃 충돌 2개, 여러 칸을 합친 과거 도식 분석 1개, 공간 부족 1개다.

사용자가 확인 가능한 검토 표시를 추가했지만, 원문 손상이나 문자 누락이 확인된 배치를 ‘적용 성공’으로 바꾸지는 않는다. 모든 셀의 강제 동일 크기, 페이지를 넘는 자동 재흐름, OCR 의미 오류 교정은 이번 범위에 포함하지 않았다. 작은 글자와 스캔 경계는 실제 크기에서도 확인하는 것이 필요하다.
