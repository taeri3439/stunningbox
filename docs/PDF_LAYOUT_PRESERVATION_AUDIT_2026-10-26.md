# PDF 구조·레이아웃 보존 점검

검증일: 2026-10-26 (Asia/Seoul). 기존 번역 API·요청 스키마·언어 설정·번역 캐시는 변경하지 않았다. 수정 범위는 `pdf-layout-lab`의 분석, 좌표 처리, 조판 안전성, 검증 및 이에 연결된 영역 편집 화면이다. `backend`/`frontend` 구현은 검토·회귀 검증하고 유지했다.

## 처리 경로와 실제 보존 범위

| 단계 | PDF 직접 조판 경로 | 기존 HTML/DOCX 경로 |
|---|---|---|
| 업로드 | `app.py:upload` → `inspect.inspect_pdf`; 원본 복사·해시, 페이지·글자 좌표 수집 | `backend/main.py:upload` → `pipeline/process.py` |
| 구조 분석 | `enhanced.prepare/analyze_page`; PyMuPDF 텍스트·글꼴·표·이미지·도형, Tesseract/RapidOCR 보완 | `extractor` → 비전/휴리스틱 `analyzer` → `reconciler` 의미 모델 |
| 원문 연결 | `native_refinement`, `translation_units`: 불변 원본 영역 → 번역 단위 → 배치 공간 | `SemanticDocument`, 블록·세그먼트 ID |
| 번역 | `legacy.translate_shared` → `unit_translation` → 기존 provider API; ID·원문·문맥 대조와 캐시 | 기존 `pipeline/translator.py`, 용어집·참고 문서·번역 메모리 |
| 적용 | 원본 PDF 복사, 안전한 텍스트만 삭제 후 Story/HTML 조판. 원본 이미지와 벡터 객체 유지 | HTML/DOCX 재구성. 원본 PDF 객체를 그대로 보존하는 경로는 아님 |
| 검증 | 임시 페이지 사전 배치 검사 + 저장 PDF의 구조/텍스트/픽셀 비교 | 기존 diagnostics 및 렌더러 테스트 |
| 출력 | 기본 PDF, 별도 편집용 DOCX/조건부 PPTX, 보고서 JSON | HTML, DOCX, OnlyOffice PDF 미리보기 |

사용 라이브러리: PyMuPDF 1.27.2.3, Pillow, OpenCV, RapidOCR, Tesseract 언어 모델, FastAPI, python-docx. 검증 PNG는 엔진과 다른 렌더러인 Poppler `pdftoppm`으로도 생성했다. 직접 PDF의 페이지 수를 고정하는 경로와 Word 흐름 기반 재배치를 혼동하지 않았다.

## 확인된 문제와 수정

1. **문구 의존 분기**: `typography.vertical_process_parts`가 열 제목이 정확히 `Step`일 때만 세로 한글 항목을 회전했다. 짧은 상위 셀, 같은 열의 정렬, 세로 글자 형상을 이용하도록 변경했다. Step/Phase/Column Z/단계에 같은 결과를 검증했다. 이 제한된 세로 항목 규칙을 임의 방향 본문 지원으로 확대 해석하지 않는다.
2. **회전 좌표 혼용**: 정밀 분석은 회전 페이지를 거절했고, OCR 래스터와 추출 좌표는 서로 다른 좌표계를 사용할 수 있었다. `geometry.py`에서 좌표 처리를 분리하고 분석·OCR 자르기·refinement·조판은 비회전 좌표로 수행한다. 원본 CropBox·회전은 출력에 유지하고 화면 표시·드래그는 양방향 변환한다. 회전과 CropBox가 함께 있는 경우 Story 삽입 위치가 어긋나는 현상도 합성 PDF로 재현하고 수정했다.
3. **삭제 범위의 이웃 글자 손상 가능성**: 기존 15% 겹침 허용은 PyMuPDF의 삭제 동작과 맞지 않았다. 글자 경계가 조금만 겹쳐도 삭제될 수 있다. 원본의 실제 글자 좌표와 해당 영역의 소유 좌표를 대조하며, 모델에서 빠진 글자도 보호한다. 수동 확인으로 이 검사를 우회하지 않는다. 기존 삭제 주석이 있는 페이지는 그 주석을 실행하지 않는다.
4. **조판 성공값만 신뢰**: 모든 FIT 영역에 번역문 완전성, glyph 경계, 원본 이웃 글자·이미지·도형·스캔 잉크 및 앞서 배치한 번역문과의 충돌 검사를 적용했다. 폰트 ascender 전체 높이를 실제 잉크로 간주하는 오탐을 피하기 위해 trace glyph 기하를 사용한다. 기존 공간 회복 후에도 다시 검사한다. 이미지 배경 패치를 모두 그린 다음 번역문을 넣어 뒤의 패치가 새 글자를 가리지 않게 한다.
5. **검증 누락과 오탐**: UNCHANGED를 무조건 통과시키던 처리를 제거했다. 원문 네이티브 글자·위치·크기·색·스타일을 비교하고, 텍스트 레이어가 없는 OCR 원문은 이미지로 비교한다. 셀 경계에 걸친 다른 영역의 실제 유지 글자는 새 번역문에 섞어 세지 않는다. 픽셀 검사는 기존 72dpi/명도 차이 12 초과 기준을 동일하게 적용한다.
6. **개수만 검사하던 구조 검증**: 링크 목적지·위치, 주석 내용/속성, 폼 이름/값, 목차/책갈피 목적지, 페이지 번호 체계, 문서 메타데이터, 이미지 내용/변환, 벡터 도형 속성을 비교한다. 객체 번호는 저장 시 바뀔 수 있어 비교에서 제외한다. 페이지 수나 크기가 달라도 검증기가 예외로 종료되지 않고 실패 사유를 반환한다. 검증 버전을 저장해 예전 보고서의 미검증 페이지를 새 검사 통과로 재사용하지 않는다.
7. **서식 손실**: FIT 대체 글꼴을 모두 sans-serif로 고정하던 부분에 serif/monospace 구분을 적용했다. 간격 보존을 끈 경로에서도 기울임을 유지한다. 원본 임베디드 글꼴과 다른 언어의 glyph coverage를 완벽히 대응시키는 기능은 추가하지 않았다.
8. **OCR 실패와 진단**: 로컬 OCR/이미지 검출 오류를 페이지별 코드와 상세 사유에 남기고 원본 시각 요소와 추출 가능한 본문을 유지한다. `reason_code`, `failure_type`, `placement_checks`로 배치 결과를 구분한다. 문서 전체의 구조 변경 사유도 화면에 표시한다.
9. **중복 경계 처리**: 공간 회복에서 이미지·선·곡선·주석 장애물을 따로 만들던 코드를 공통 `graphics()`로 통합했다.

공식 동작 근거: [PyMuPDF Page API](https://pymupdf.readthedocs.io/en/latest/page.html)의 비회전 좌표 규칙과 `apply_redactions`의 문자/링크 겹침 처리. 실제 설치 버전에서 별도로 재현·검증했다.

## 하드코딩으로 단정하지 않은 부분

- 런타임 엔진에서 특정 업로드 파일명이나 문서 ID를 골라 처리하는 분기는 확인하지 못했다. 테스트의 특정 파일명은 회귀 사례이며 런타임 분기와 구별했다.
- `CairoFont-...` 식별은 특정 PDF 생성기의 폰트 정보 결손을 보완하는 제한된 처리다. 같은 글자들의 실제 획 밀도를 비교한다. 모든 글꼴에 이 추론을 적용하도록 확대하지 않았다.
- 표 셀 여백, 근접 줄 병합, 목록/체크 기호, 반복 머리말 범위, 안전 거리, 최소 글자 크기 등 수치·정규식은 휴리스틱과 정책이다. 실제 셀·글자·객체 경계와 함께 사용하는 곳까지 일괄 삭제하지 않았다. 오분류 가능성은 여전히 있으며, 페이지 전체를 문단 흐름으로 재구성하는 근거로 사용하지 않는다.
- 원본 배치 영역의 확대는 기존 셀/열·이웃 객체의 경계 안에서 수행한다. 이번 작업은 이를 전면 재작성하지 않고 삭제·배치·출력 검증을 보강했다.

## 보존 대상과 한계

| 대상 | 현재 처리·한계 |
|---|---|
| 페이지 수·순서·크기·방향·CropBox/MediaBox/TrimBox/BleedBox/ArtBox | 직접 PDF 경로는 유지·검증. 페이지 밖 이동이나 페이지 추가 없음 |
| 제목·문단·다단·목록·들여쓰기·행간 | 추출된 원본 위치, 글꼴, 목록 기호, 기존 문단 연결 규칙을 활용. 긴 문장은 단어 단위 재조판. 언어가 달라진 뒤 모든 원본 행에 1:1 대응시키지 않음 |
| 긴 번역·셀 넘침·하단 부족 | 원본 크기 → 내부 여백/행간 → 단어 줄바꿈 → 허용된 셀/열 공간 → 제한된 축소. 실패 시 원문 유지와 사유 제공. 페이지를 넘기는 자동 재흐름은 미지원 |
| 머리글·바닥글·페이지 번호·각주·캡션 | 위치와 원본 객체를 유지. 번역되지 않은 부분의 글자·서식도 검사. PDF에서 각주/미주/캡션의 논리 연결이나 자동 번호 갱신을 일반적으로 복구하지는 않음 |
| 목차·제목 수준·책갈피·하이퍼링크 | 기존 PDF outline/목적지/페이지 라벨 유지·검증. 본문의 제목 의미 트리나 접근성 태그를 새로 만들지 않음. 링크와 겹친 번역 영역은 원문 유지 |
| 글꼴·색·굵기·기울임·특수문자 | 원문 유지 영역은 원본 속성 유지. 번역 영역은 대응 가능한 대체 계열/서식과 문자 검사. 임의 혼합 run의 강조, 밑줄, 자간, 수식 의미 구조는 완전 보존 보장 없음 |
| 표·병합 셀·테두리·배경·반복 머리글 | PDF 선·배경 및 셀 기하 유지. 병합 셀/여러 행을 시험. 직접 PDF는 표의 페이지 재분할이나 새 반복 머리글을 생성하지 않음 |
| 이미지·도형·차트·텍스트 상자·겹침 순서 | 원본 시각 객체 유지. 텍스트만 안전한 범위에서 교체. 차트 데이터, 수식 편집 모델, 객체 의미 트리는 복원하지 않음 |
| 스캔·윤곽선 글자 | OCR로 읽은 위치의 국소 패치 적용. 복잡한 사진·그라데이션, 불명확한 위치, OCR 판독 불가는 유지/검토. OCR 정확도·서명·고유명사의 의미 정확성은 별도 검토 필요 |
| 회전 | 페이지의 0/90/180/270도 회전 지원. 페이지 안의 임의 방향 글자와 투명 겹침은 기존 보호 규칙 적용 |
| PDF→DOCX/PPTX | 텍스트 상자와 배경 이미지 방식. 편집 가능한 Word 표·차트의 일반 복원이 아님. 회전된 글자는 DOCX에서 배경에 남을 수 있음. OnlyOffice 재렌더링 차이는 이번 직접 PDF 검사와 별도 |

## 검증

기존 테스트를 삭제하거나 기대치를 완화하지 않았다. 로컬 API 키를 호출하지 않고 저장된 번역문과 테스트 번역을 사용했다. 실제 번역 의미 품질과 운영 중 외부 API/OnlyOffice의 가용성은 이번 검증 대상이 아니다.

- PDF Lab 전체 테스트: 수정 전 166개, 수정 후 **206개 통과**(기존 166개 + 추가 40개). 경고 1개.
- 추가 테스트: 회전×CropBox 조합, 혼합 페이지 크기, 단순 본문, 다단·각주·목록, 병합 표, 도형·차트·이미지·텍스트 상자, 글꼴 계열·기울임, 한→영 확장, 24페이지 문서, 회전 스캔 OCR, OCR 엔진 실패, 불완전 조판, 작은 삭제 겹침, 모델에서 누락된 글자, 기존 삭제 주석, 수동 번역문 충돌, 셀 경계의 유지 글자, 링크/주석/폼/목차 변조, 페이지 누락/크기 변화, 구형 검증 보고서 재사용 방지.
- 뷰어 좌표: Node 테스트 2개(각 회전의 기하와 여러 페이지 크기에서 왕복 변환).
- 기존 backend: 610개 통과, 환경 의존 11개 skip. backend 코드는 변경하지 않았다.
- 합성 시각 검증: 6종 × 3페이지 = 18페이지. 5종은 구조·텍스트·영역 밖 픽셀 검사 통과. 과도한 길이 1종은 3개 영역을 모두 원문으로 유지하고 NEEDS_REVIEW. 모든 경우 원본 이미지/벡터 및 페이지 기하 유지, 영역 밖 변경 픽셀 0.
- Poppler로 합성 18페이지와 실제 2/4/34페이지 문서의 원본·출력, 총 **58페이지 쌍**을 렌더링했다. 본문 확장·짧아짐, 표/도형/다단, 회전된 표와 작은 스캔 라벨을 비교했다. 자동 검사는 모든 페이지에 수행하고 육안 검토는 대표 비교 이미지와 상세 영역을 사용했다. 모든 페이지를 사람이 정밀 판독한 것은 아니다.

실제 4/34페이지 저장 문서의 같은 원문·레이아웃·번역 정책을 수정 전 HEAD 코드의 별도 복사본과 수정 코드에서 각각 재실행했다. 2페이지 문서는 저장된 정상 결과와 비교했다. 수정 전 모듈은 `tmp/pdfs/layout-preservation-baseline`에만 복사했다. 기존 업로드·실행·캐시는 변경하지 않았다. 과거 저장 보고서의 수치와 새로 재실행한 수정 전 기준값은 다를 수 있다.

- 새 테스트: `pdf-layout-lab/tests/test_layout_preservation.py`, `tests/test_geometry.cjs`
- 오프라인 검증 도구: `pdf-layout-lab/check_preservation.py`
- 생성 사례별 PDF·원본/결과 PNG·비교 이미지·JSON: `output/pdf/layout-preservation/`

- 각 `summary.json`의 `before`는 **과거 저장 보고서**, `after`는 **해당 도구 실행 결과**다. 현재 작업 전후 비교는 `baseline-*/summary.json.after`와 `real-*/summary.json.after`를 비교한다.

```powershell
cd pdf-layout-lab

node --test tests/test_geometry.cjs
../backend/.venv/Scripts/python.exe check_preservation.py ../output/pdf/layout-preservation
# 실제 저장 실행: 원본/기존 실행과 다른 출력 폴더를 지정
../backend/.venv/Scripts/python.exe check_preservation.py OUTPUT --saved-run RUN_DIRECTORY --source SOURCE_PDF
```
