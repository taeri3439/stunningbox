# Stunningbox 개발 진행 정리

> 정리 기준: 2026년 10월 26일 · 현재 소스 코드와 로컬 변경 사항 기준

## 1. 프로젝트 목표

PDF의 제목·문단·표·그림·목록 등 문서 구조를 최대한 유지하면서 번역하고, 원본과 결과를 비교하며 필요한 부분을 직접 수정할 수 있는 문서 번역 도구를 개발하고 있습니다.

## 2. 현재 구성

| 구성 | 역할 | 로컬 포트 |
|---|---|---|
| Backend | PDF 추출·구조 분석·번역·문서 출력 API | 8000 |
| Frontend | 기존 Next.js 웹 화면 | 3000 |
| PDF Layout Lab | 영역 기반 번역·직접 PDF 조판·비교·품질 검토 실험실 | 8011 |
| OnlyOffice 연동 | DOCX 편집 및 PDF 변환·미리보기 | 별도 서비스 설정 |

기존 프로젝트 파이프라인과 새 PDF 조판 경로를 비교할 수 있으며, 새 경로만 실행하는 옵션도 제공합니다.

## 3. 구현한 주요 기능

### 문단 단위 분석과 번역

- PDF의 물리적인 줄을 문단·목록·표 셀 경계에 맞게 다시 묶습니다.
- 원문 영역, 의미상 번역 단위, 번역문 배치 공간을 분리해 관리합니다.
- 원문 좌표·폰트·색상·강조 정보를 보관하고 문단 전체를 번역합니다.
- 번역 응답의 ID와 원문을 대조해 다른 영역의 번역문이 잘못 연결되는 문제를 검사합니다.
- 문장 캐시, 묶음 번역, 제한된 오류 복구 및 API 시간 통계를 제공합니다.
- OpenAI 클라이언트를 주입할 수 있도록 기존 공통 호출 함수를 보완했습니다.

### 레이아웃과 서식 보존

- 문단의 들여쓰기·여백·행 간격·정렬과 제목·본문의 크기 및 굵기를 복원합니다.
- 목록 번호, 체크 표시, 점선 항목과 수량, 반복 머리말, 세로 공정명을 별도 처리합니다.
- 워터마크·그림·연결선 등 보호 대상과 번역 영역을 구분합니다.
- 공간이 부족하면 주변 장애물을 고려해 제한적으로 배치를 복구하고, 해결되지 않으면 원문 유지 사유를 남깁니다.
- 최종 PDF의 번역문 반영 여부와 배치 품질을 검사합니다.

### 결과 비교와 영역 편집

- 원본 PDF, 새 레이아웃 결과, 기존 프로젝트 결과를 비교합니다.
- 한 영역 또는 선택한 여러 영역의 교체문을 번역 API 호출 없이 적용합니다.
- 같은 페이지 영역을 병합하고 번역문 배치 박스를 이동·조절할 수 있습니다.
- 선택 영역만 다시 번역하고 적용하는 기능을 제공합니다.
- 가능한 경우 변경된 페이지만 재조판하고 이전 실행 결과를 보존합니다.
- DOCX는 필요할 때 준비하며, 오래된 편집본이 최신 결과로 제공되는 것을 방지합니다.

### 대시보드와 품질 검토

| 화면 | 제공 기능 |
|---|---|
| 새 번역 | 파일 업로드, 언어 선택·교환, 실행 방식 선택, 최근 작업 |
| 결과 비교 | 영역 편집, 결과 확대, 이전 실행 PDF·보고서 열기 |
| 품질 관리 | 원문·교체문·미반영 사유 검색, 검토 필터, 영역 이동 |
| 작업 기록 | 저장 문서 검색, 실행 이력 및 결과 다시 열기 |
| 설정 | 언어·확대·스크롤 동기화 등 브라우저 기본값 저장 |

사용자 검토의 확인 완료·수정 요청·메모는 별도 기록으로 저장합니다. 사용자 확인이 자동 검사 결과나 PDF를 변경하지는 않습니다. 작업 중지는 처리 묶음 사이에서 협력적으로 수행합니다.

### 문서 출력과 편집

- 직접 조판한 PDF와 줄별 텍스트 상자 방식 DOCX를 생성합니다.
- OnlyOffice에서 DOCX를 편집하고 저장 후 PDF 미리보기를 갱신합니다.
- Smart Export는 입력 형식과 실제 변환 가능 여부에 따라 출력 항목을 제공합니다.
- DOCX·PPTX·HWPX는 기존 패키지의 텍스트를 교체하는 경로가 있습니다.
- DOC·HWP는 원본 형식 번역 저장을 지원하지 않으며, 원본 보존과 변환 성공 시 추가 출력을 제공합니다.

## 4. 개발·실행 편의

프로젝트 루트에서 다음 명령으로 로컬 서비스들을 실행할 수 있습니다.

```powershell
.\scripts\start-all-local.ps1
```

사전에 Python 가상환경, 두 Python requirements의 의존성, 프론트엔드 의존성, API 및 OnlyOffice 설정이 필요합니다. 이미 사용 중인 포트의 서비스는 건너뛰며 로그는 `_local-logs`에 저장합니다.

## 5. 현재 제약과 확인할 부분

- 현재 단계는 로컬 실험·검증용이며, 모든 문서의 서식을 완벽히 재현하는 상태는 아닙니다.
- 긴 번역문, 좁은 표 셀, 부정확한 OCR, 회전 글자 등은 원문 유지 또는 추가 검토가 필요할 수 있습니다.
- PDF 기반 DOCX의 표 선·그림은 배경 이미지이며, Word의 실제 표나 개별 도형으로 복원되지 않습니다.
- DOCX 편집 후 Word/OnlyOffice의 글꼴과 줄바꿈 차이로 결과가 달라질 수 있습니다.
- 자동 검사는 픽셀 단위 동일성이나 번역 의미의 정확성을 보증하지 않습니다.
- 이미지 글자·차트·슬라이드 마스터·삽입 개체의 번역 범위는 입력 형식별로 다릅니다.
- 실제 외부 번역 API, OnlyOffice 및 다양한 실문서에 대한 종합 품질 확인은 별도로 필요합니다.

## 6. 다음 작업 제안

1. 대표 실문서로 원문·PDF·DOCX를 비교하고 미반영 영역을 검토합니다.
2. 긴 문단·복잡한 표·스캔 문서에서 배치 실패와 OCR 오류 사례를 모읍니다.
3. 번역 정확도, 레이아웃 보존, 처리 시간을 나누어 품질 기준을 정합니다.
4. 검증된 로컬 기능을 기준으로 배포·운영 범위를 정합니다.

## 7. 이번 Git 반영 범위

소스, 대시보드 정적 파일, 회귀 테스트, 실행 스크립트와 문서를 반영합니다. 업로드 원본과 실행 산출물(`pdf-layout-lab/data/`), `output/`, `tmp/`는 이번 커밋에서 제외합니다. 기존에 추적 중인 파일은 제거하지 않습니다.

## 8. 이번 검증 결과

- PDF Layout Lab 회귀 테스트: **166개 통과** (31.90초).
- FastAPI/Starlette 테스트 클라이언트의 httpx 관련 사용 중단 경고 1건이 있습니다.
- 실제 유료 번역 API 및 OnlyOffice 실서버 통합 검증은 이번 검사에 포함하지 않았습니다.
